# 1 АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ И ОБЩАЯ ПОСТАНОВКА ЗАДАЧИ

## 1.1 Описание предметной области

Предметной областью работы является самостоятельная работа студента с учебными материалами курса. Материалы представлены PDF-файлами: конспектами лекций, методическими пособиями, учебниками и справочниками. Корпус охватывает семь тематических направлений: Computer Science, Git, Linux, SQL и базы данных, алгоритмы и структуры данных, компьютерные сети, объектно-ориентированное программирование.

Типичный сценарий выглядит так: студент готовится к занятию или экзамену, формулирует вопрос («чем отличается merge от rebase», «как выбрать индекс для составного условия», «почему деструктор базового класса должен быть виртуальным») и хочет получить короткий ответ с указанием месте в материале, где это написано. Сложность состоит в том, что вопрос формулируется обычным языком, а материал хранится в виде больших документов с оглавлениями, рисунками, формулами и листингами кода.

Учебные материалы обладают рядом особенностей. Во-первых, они неоднородны по объёму и качеству: в корпусе есть как небольшие шпаргалки на две страницы, так и учебники на тысячу страниц. Во-вторых, часть страниц не содержит текстового слоя: это сканы, титульные листы, страницы с преобладанием рисунков. В-третьих, терминология смешанная: русские термины соседствуют с английскими названиями команд, библиотек и аббревиатур. В-четвёртых, ответ часто распределён по нескольким абзацам, а иногда — по нескольким страницам, поэтому поиск должен возвращать не один фрагмент, а набор взаимодополняющих фрагментов.

Перечисленные особенности определяют требования к интеллектуальной системе: она должна понимать смысл вопроса, находить релевантные фрагменты в разнородном корпусе, формировать связный ответ на русском языке и обязательно показывать источник. Система не должна «додумывать» факты, которых нет в материалах, потому что цена ошибки в обучении высока.

## 1.2 Обзор существующих подходов

Можно выделить четыре группы решений, которые применяются для поиска ответов по учебным материалам.

**Полнотекстовый поиск** (встроенный поиск PDF-просмотрщика, `grep`, Elasticsearch) работает по точным словам и морфологии. Он быстрый и прозрачный, но не понимает синонимы и перефразирования: запрос «как отменить последний коммит» может не найти фрагмент со словом «revert». Качество сильно зависит от того, насколько удачно студент угадал формулировку.

**Форумы и чаты курса** хранят ответы преподавателей и студентов, но они плохо структурированы, содержат устаревшие сообщения и не привязаны к страницам учебника. Поиск по ним обычно ограничен точным совпадением, а качество ответа зависит от того, кто и когда его написал.

**Универсальные чат-боты** (ChatGPT, Claude и аналоги) демонстрируют хорошее понимание языка и умеют объяснять сложные понятия. Однако без доступа к материалам курса они отвечают по общим знаниям: могут перепутать версию технологии, сослаться на несуществующий раздел или выдать правдоподобную, но неверную деталь. Для учебной задачи это создаёт риск распространения ошибок.

**RAG-системы** сочетают поиск по внешнему корпусу и генерацию. Сначала система находит релевантные фрагменты, затем передаёт их языковой модели вместе с вопросом и требованием отвечать только по контексту. Такой подход сохраняет естественность ответа, но делает его проверяемым: каждое утверждение можно сопоставить с источником. RAG не требует переобучения модели при обновлении материалов — достаточно переиндексировать корпус.

Сравнение подходов приведено в таблице 1.1.

| Таблица: Сравнение подходов к поиску ответов по учебным материалам
| Критерий | Полнотекстовый поиск | Форумы курса | Универсальный чат-бот | RAG |
| --- | --- | --- | --- | --- |
| Понимание смысла вопроса | Низкое | Низкое | Высокое | Высокое |
| Ссылка на источник | Есть | Частично | Нет | Есть |
| Актуальность материалов | Высокая | Средняя | Низкая | Высокая после переиндексации |
| Риск галлюцинаций | Нет | Средний | Высокий | Низкий при строгом промпте |
| Стоимость эксплуатации | Низкая | Низкая | Средняя | Средняя |
| Сложность реализации | Низкая | Низкая | Низкая | Средняя |

RAG выигрывает по совокупности критериев: он сохраняет смысловое понимание вопроса, даёт проверяемые ссылки и обновляется без обучения модели. Именно этот подход выбран для дальнейшей реализации.

## 1.3 Формальная постановка задачи

Пусть задан корпус документов D = {d1, d2, …, dN}, где каждый документ состоит из страниц di = {pi1, pi2, …, piM}. Корпус разбивается на чанки C = {c1, c2, …, cK}, каждому чанку сопоставлены метаданные: идентификатор документа, название, тема, номер страницы и текст.

Входные данные системы:

- вопрос студента q — строка длиной от 1 до 2000 символов на русском или английском языке;
- необязательный фильтр по теме t;
- необязательное число фрагментов k (от 1 до 12);
- необязательный провайдер и модель LLM.

Выходные данные:

- текст ответа a;
- список источников S = {(di, pij, sj)}, где sj — оценка релевантности;
- служебные метрики: количество токенов, скорость генерации, время поиска и генерации;
- признак отказа, если в корпусе нет достаточного контекста.

Ограничения:

- ответ формируется только по найденным фрагментам, без внешних знаний;
- язык ответа — русский;
- корпус не публикуется в открытом репозитории из-за авторских прав; в репозитории хранятся манифест, паспорт и скрипты сборки;
- вычислительные ресурсы — CPU-only, без GPU;
- внешняя LLM доступна через OpenRouter; предусмотрен локальный резерв;
- время ответа при облачной LLM не должно превышать 5 секунд для 95-го процентиля.

Формально задача состоит в построении функции F(q, t, k) → (a, S), которая максимизирует обоснованность ответа (faithfulness) при сохранении релевантности вопросу.

## 1.4 Требования к системе

На основе анализа предметной области сформулированы функциональные и нефункциональные требования.

| Таблица: Функциональные требования
| Код | Требование |
| --- | --- |
| F1 | Принимать вопрос студента и возвращать ответ на русском языке |
| F2 | Находить релевантные фрагменты в корпусе PDF-материалов |
| F3 | Показывать источник: документ, страницу, фрагмент и оценку релевантности |
| F4 | Поддерживать фильтрацию поиска по теме |
| F5 | Отказываться от ответа, если в материалах нет достаточного контекста |
| F6 | Загружать новые PDF и запускать индексацию без перезапуска системы |
| F7 | Показывать список документов, статусы и прогресс индексации |
| F8 | Вести историю чатов и экспортировать её |
| F9 | Предоставлять REST API с валидацией и документацией OpenAPI |
| F10 | Показывать метрики работы агента: токены, токены в секунду, задержки |

| Таблица: Нефункциональные требования
| Код | Требование |
| --- | --- |
| NFR1 | Время ответа p95 ≤ 5 с при облачной LLM |
| NFR2 | Пропускная способность ≥ 1 запрос/с при concurrency = 3 |
| NFR3 | Потребление RAM контейнера ≤ 4 ГБ |
| NFR4 | Воспроизводимость: фиксированные версии зависимостей, Docker, CI |
| NFR5 | Безопасность: секреты не попадают в Git, входные данные валидируются, CORS ограничен |
| NFR6 | Приватность: материалы не отправляются в LLM целиком, только найденные фрагменты |
| NFR7 | Расширяемость: замена модели эмбеддингов, LLM и векторной БД без переписывания логики |

**Основная метрика качества — Faithfulness (RAGAS).** Она измеряет долю утверждений в ответе, которые подтверждаются найденным контекстом. Выбор обусловлен природой задачи: ответ — свободный текст, а не класс, поэтому Accuracy и F1 неприменимы. Главный риск RAG — галлюцинации, и именно Faithfulness измеряет этот риск напрямую. Целевое значение — не менее 0,80: для учебного ассистента недопустимо, чтобы большинство утверждений не имело опоры в материалах.

**Дополнительные метрики:** Answer Relevancy (цель ≥ 0,75) показывает, насколько ответ отвечает на вопрос; Context Precision и Context Recall характеризуют качество поиска; Answer Correctness сравнивает ответ с эталоном. Такой набор покрывает все компоненты RAG: поиск, генерацию и соответствие вопросу.

## 1.5 Выводы по разделу

Проведён анализ предметной области, рассмотрены четыре подхода к поиску ответов, обоснован выбор RAG. Сформулированы формальная постановка задачи, функциональные и нефункциональные требования, выбрана основная метрика качества и её целевое значение. Определены ограничения: CPU-only, русскоязычный корпус, необходимость ссылок на источники и запрет на публикацию полных PDF.
