# 6 АНАЛИЗ КАЧЕСТВА РЕЗУЛЬТАТОВ

## 6.1 Методика оценки

Оценка проводилась на отложенной тестовой выборке из 30 вопросов, по 4–5 на каждую тему. Для каждого вопроса известен эталонный ответ и страница-источник. Тестовая выборка не использовалась при выборе top-k, размера чанка и версии промпта; эти параметры настраивались на валидационной выборке из 10 вопросов.

Использован RAGAS 0.3.9. Судья — `meta-llama/llama-3.1-70b-instruct` через OpenRouter, эмбеддинги для метрик — USER2-base. Рассчитаны метрики:

- **Faithfulness** — доля утверждений ответа, подтверждённых контекстом;
- **Answer Relevancy** — соответствие ответа вопросу;
- **Context Precision** — доля релевантных фрагментов среди найденных;
- **Context Recall** — доля информации эталонного ответа, покрытая контекстом;
- **Answer Correctness** — близость ответа к эталону с учётом фактов и семантики.

Дополнительно рассчитана доля вопросов, для которых gold-страница попала в top-k (gold hit). Для каждой метрики приведено среднее значение и 95 % бутстрэп-доверительный интервал (1 000 ресэмплов). Baseline — та же LLM без поиска: она получает только вопрос и отвечает по общим знаниям.

## 6.3 Анализ ошибок

Для анализа выбраны 10 ответов с наименьшим Faithfulness или Answer Correctness. Типичные причины ошибок:

1. **Промах поиска.** Нужная страница не попала в top-k из-за иной формулировки вопроса; BM25 не нашёл точных слов, а плотный индекс не покрыл этот чанк (подвыборка).
2. **Граница чанка.** Ответ распределён между двумя чанками, и в контекст попал только один; модель дополнила ответ по соседнему фрагменту.
3. **Скан или формула.** Страница не имеет текстового слоя либо формула извлечена как последовательность символов; контекст не содержит нужного утверждения.
4. **Многошаговый вопрос.** Требуется объединить факты из двух документов; top-k содержит только один.
5. **Неоднозначность.** Вопрос допускает несколько трактовок; эталонный ответ соответствует одной, модель выбирает другую.
6. **Устаревшая версия.** В корпусе две версии учебника; найдена страница с отличающейся формулировкой.
7. **Языковой разрыв.** Вопрос по-русски, источник — англоязычная шпаргалка; модель переводит, но теряет точность.
8. **Избыточность.** Модель добавляет общеизвестные детали, которых нет в контексте; Faithfulness снижается.
9. **Отказ.** Система отказывается отвечать, хотя ответ в корпусе есть; причина — низкий dense-score или фильтр по теме.
10. **Ошибка судьи.** RAGAS-судья иногда считает корректное утверждение не подтверждённым из-за перефразирования.

## 6.5 Ограничения решения и направления улучшения

Ограничения:

- плотный индекс построен по стратифицированной подвыборке (до 25 чанков на документ), поэтому редкие фрагменты могут не иметь плотного вектора; BM25 частично компенсирует это;
- PDF-сканы без текстового слоя не индексируются;
- формулы, таблицы и код извлекаются с потерей структуры;
- корпус несбалансирован: Git и ООП представлены слабо;
- LLM зависит от внешнего API; при недоступности используется более слабая локальная модель;
- RAGAS-судья может ошибаться, поэтому метрики следует рассматривать вместе с анализом ошибок;
- полноценный OCR всех сканов на CPU занял бы часы и не входил в рамки прототипа.

Направления улучшения:

1. Добавить OCR для сканов (Tesseract/PaddleOCR) и проверить прирост Recall.
2. Построить полный плотный индекс на GPU или с ONNX-квантованием.
3. Добавить реранкер (например, bge-reranker) для повышения Context Precision.
4. Реализовать перефразирование запроса и HyDE для сложных вопросов.
5. Расширить корпус Git и ООП, добавить учебник Pro Git.
6. Ввести мониторинг качества в эксплуатации: собирать обратную связь и периодически пересчитывать RAGAS.
7. Добавить кэширование ответов и стриминг для снижения задержки.

## 6.6 Выводы по разделу

Проведена количественная оценка на отложенной выборке из 30 вопросов. RAG превосходит baseline по обоснованности и точности, достигает целевых значений по Faithfulness и Answer Relevancy. Выполнен анализ ошибок, выделены причины и направления улучшения. Ограничения решения зафиксированы; они связаны с CPU-конфигурацией, качеством PDF и размером корпуса.
