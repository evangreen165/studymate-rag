### 4. Как можно отменить изменения, сделанные в файле, и вернуться к версии файла из последнего коммита?

**Ответ:** Чтобы отменить изменения, сделанные в файле, и вернуться к версии файла из последнего коммита, можно использовать команду `git checkout -- [file]` [1]. Эта команда отменит изменения в рабочем каталоге, и файл вернется к версии из последнего коммита. Однако, пожалуйста, обратите внимание, что эта операция необратима.

Альтернативно, можно использовать команду `git reset --hard HEAD~1` [2], чтобы отменить изменения и вернуться к предыдущей версии файла. Однако, эта команда отменит все изменения, сделанные в последнем коммите, а не только изменения в конкретном файле.

**Эталон:** Для этого можно воспользоваться командой git reset --hard [commit], где [commit] - хеш последнего коммита. Эта команда очистит область подготовки и переписать рабочее дерево из указанного коммита.

### 6. Как можно эффективно реализовать агрегатные запросы, если значения хранятся в списке, разделенном запятыми?

**Ответ:** Для эффективной реализации агрегатных запросов, если значения хранятся в списке, разделенном запятыми, можно использовать разные подходы. Например, можно вычислять длину строки со значениями, разделенными запятыми, за вычетом длины строки с удаленными запятыми, чтобы получить количество элементов в списке [2]. Однако этот подход может быть неочевидным и сложным для отладки. 

Более эффективный подход - использовать таблицу пересечений, в которой каждое значение хранится в отдельном столбце и строке [4]. Это позволяет использовать индексы и агрегатные функции более эффективно. Кроме того, можно добавлять дополнительные атрибуты для каждого элемента, что невозможно сделать с списком, разделенным запятыми. 

Также можно использовать функции, такие как string_to_array() в PostgreSQL, чтобы преобразовать строку, разделенную запятыми, в массив, а затем использовать функцию unnest(), чтобы расширить массив в набор строк [4].

**Эталон:** Агрегатные запросы можно реализовать с помощью функций, таких как COUNT(), SUM() и AVG(), но для этого необходимо использовать ухищрения, например, вычислять длину строки со значениями, разделенными запятыми, за вычетом длины строки с удаленными запятыми. Однако такие решения неочевидны и требуют много времени на разработку и отладку. Некоторые агрегатные запросы вообще невозможно реализовать.
